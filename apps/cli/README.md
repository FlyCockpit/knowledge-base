# kb

Companion Rust CLI for the knowledge-base. Apache-2.0. Lives at `apps/cli`,
outside the pnpm/Turborepo graph — all work here happens with `cargo`.

```sh
cd apps/cli
cargo test --workspace --all-targets --locked
cargo run -- --help
cargo run -- config path
```

## Install

Download `kb` 1.0.0 from [GitHub Releases](https://github.com/FlyCockpit/knowledge-base/releases). Releases provide platform archives, shell and PowerShell installers, `sha256.sum` checksums and `THIRD_PARTY_LICENSES.html` generated by cargo-about. Verify your archive against the release checksum file, for example on Linux x64:

```sh
grep 'kb-x86_64-unknown-linux-musl\.tar\.xz$' sha256.sum | sha256sum -c -
```

The Linux archives (`kb-x86_64-unknown-linux-musl.tar.xz`,
`kb-aarch64-unknown-linux-musl.tar.xz`) contain a fully static binary: no
glibc version floor and no C++/OpenMP runtime to install; local embeddings keep
llama.cpp's OpenMP threading. Being static, the Linux binary resolves host
names from `/etc/hosts` and DNS only: it does not load NSS modules, so names
that only resolve through `/etc/nsswitch.conf` plugins (mDNS `*.local`, LDAP,
sssd) need DNS or an `/etc/hosts` entry. macOS and Windows binaries link their
platform C++/OpenMP runtimes, as described in the build requirements below.

Remote credentials are separate from `config.toml`:

```sh
kb config set-server https://kb.example
kb login --name Laptop
kb logout
```

Serve MCP over stdio with an explicit backend:

```sh
kb mcp --root /private/store
kb mcp --server https://kb.example
```

With no backend flag, `mcp` uses `root` or `server` in `config.toml`
(`kb config set-root <path>` / `kb config set-server <url>`); setting both
requires an explicit selection. An explicit flag overrides the configured
backend. `--root` and `--server` together are rejected. `--principal` selects
only a local capability principal. `--read-only` lists only read tools on
either backend, while the remote PAT's permissions remain authoritative.

Remote startup verifies the full pinned kb/1 tool catalog and schemas before
advertising tools. Calls preserve citations, locators, domain errors and sealed
ciphertext. Sealed plaintext is available only through the separate, explicit
kb-client host resolver. Cancellation and EOF cancel and drain HTTP work.
Forwarding makes one attempt: a lost mutation reply has an unknown outcome;
retry with the same arguments and idempotency key, never a replacement key.
Protocol output goes to stdout and diagnostics go to stderr.

Download a remote ZIP with the stored PAT:

```sh
kb export --kb <knowledge-base-id> --output knowledge-base.zip
kb export --kb <knowledge-base-id> --kind assets --output assets.zip --json
```

`--rev <sha>` pins a revision. The client reads bounded MCP frames, retries
lost frame replies with the same offset, and verifies the exact size and
SHA-256 before publishing the private temporary file. Existing destinations
are refused. Only after the file and its directory are synced does the same
preparing PAT acknowledge completion and release the server export slot.
If acknowledgement fails, the saved ZIP remains valid; JSON reports
`acknowledged: false` and the server reclaims its ten-minute EOF grace.
An optional `--idempotency-key` recovers the same prepare after interruption;
it must be reused with identical KB, kind and revision arguments.

Login prints a verification URL and public user code to stderr. Open it
yourself, sign in, and choose the PAT's permissions. The CLI polls the actual
device endpoint and oRPC exchange, respecting pending/slow-down responses and
expiry. Denial or a lost consumed exchange reply requires a new login.

For sealed values, pass `--recipient-key-file /private/path/recipient.json` to
`kb login`. This is an existing host-owned X25519 private key, with JSON shape
`{"id":"<recipient UUID>","private_key":[<32 byte integers>]}`. Create it with
an OS random source in your host's key provisioning flow, store it in an
owner-only file, and keep it for `kb_client::sealed::RecipientKey::from_bytes`
and host-side decryption. The CLI uploads only the public key before displaying
the verification link. Compare the key ID/public key in the terminal and approval
page. Nothing is selected by default: select Read on the KB, enter each exact
sealed reference you own and its expiry, and explicitly add it. Enrolled two-factor
authentication is required. Ordinary login without this option grants no sealed
capability. OAuth app consent never offers sealed recipients.

Import an existing PAT using `kb login --token-stdin` with piped input, or
`kb login --token-file /private/path/token`. There is no token argument or
token-print command. Token input must contain one token of at most 8192 ASCII
bytes, optionally followed by a single line ending, with no trailing data.
Unix imports require a current-user-owned regular file with mode 0600 and no
hard links or symlink components. Windows imports require a protected DACL
granting FullControl only to the current SID.

`<data-dir>` is the per-user data directory, overridable with `KB_DATA_DIR`.
It is unrelated to the server's `KB_DATA_ROOT` data volume.

State lives in `<data-dir>/credentials`, keyed by canonical server origin
and its exact `/mcp` resource. `--server` and config changes select only that
resource's credential. Unix directories/files are 0700/0600; files publish
with atomic rename and file/directory fsync, including parent directory links
on first save. Credential I/O shares a directory lock; the next load, save, or
logout reclaims private temp files left by an interrupted writer. Windows uses DPAPI CurrentUser
and explicit owner-only ACLs through Windows PowerShell; unavailable
protection fails closed. All platforms reject symlinks/reparse points.
No token, device code, or remote error body is printed or saved to config.

Default logout calls the bearer-only, bodyless PAT self-revoke endpoint,
then deletes matching local state. Failed revocation reports the unknown
remote outcome and retains local state for retry. `kb logout --local` makes
no network request and warns that the remote token remains active. A
concurrent re-login's replacement credential is retained.

HTTPS is required. Development HTTP needs `--allow-loopback-http` on each
login/logout/export/mcp and accepts loopback only;
`kb config set-server <url> --allow-loopback-http` remembers the opt-in for
that one server. Redirects are rejected. Ambient
proxy variables are ignored; an optional `proxy = "http://127.0.0.1:8080"`
in config explicitly opts in. Proxy URLs cannot contain credentials. A proxy
can observe HTTP development traffic; use HTTPS for remote credentials.

Workspace members: the `kb` binary, `xtask`, `crates/kb-local` (on-device
managed store, hardened Git access, the shared whole-tree
validator, the durable one-ref publication journal with crash recovery, and
the local KB lifecycle and immutable document catalog, and atomic edits
with proposal ownership and reviewed PR merges),
and `crates/kb-client` (typed
kb/1 protocol contract, validated against the canonical TypeScript schema and
fixtures, plus the origin-bound stateless MCP HTTP client). MSRV 1.96.

The shared kb/1 decoder accepts safe integers by numerical value, including
JSON `1.0`, exponent notation and negative zero wherever the field permits
zero. Fractions and values outside each field's bounds still fail validation.
`SecretToken` owners and clones use `zeroize::Zeroizing<String>` and redact formatting.
Use `ToolError::new(code, details)?` to construct outgoing domain errors; it
rejects mismatched detail kinds and unsafe numeric details. Access validated
fields through `code()`, `message()`, `retryable()` and `details()`.

CI: `.github/workflows/cli-ci.yml` (working directory `apps/cli`).

The local store uses owner-only directories and files on Unix and Windows,
refuses symlinks and Windows junctions/reparse points below the canonical
root, and takes the persistent store lock before sorted KB locks. Every Git
child spawned while its store lock is held inherits that lock separately
from stdin, including `cat-file --batch` readers. Lock admission waits at most
five seconds. PR calls share a 30-second deadline across Git children and
publication checks; expired children are killed and reaped before returning. Repository membership
selects the exact store even for nested roots. Git deadlines remain active
through process exit and reaping, including after stdout closes. On Unix, surviving children
keep the lock until they exit. On Windows 10 or later, children join an
owner-held kill-on-close Job Object at creation; after owner death, successors
wait for the old job to drain before entering. Windows owner-only DACLs also
apply to newly created descendants. Existing paths with broader ACLs fail
closed. Recovery removes abandoned publication scratch only after owning the
store fence and draining former children. It reconciles only pending CAS ref
locks whose bytes match the recorded operation, propagates temporary Git
observation errors without quarantining the KB, and repeats file/directory
barriers before recovered finalization. Keyset recovery advances past retained
repair history. Windows 10+ directory publication uses the normal
`NtFlushBuffersFileEx` operation on a writable, identity-pinned directory
handle to flush metadata and the storage cache; failed or unsupported barriers
fail the operation. The required Windows CI lane selects initialization,
publication, reopen and failed-barrier checks.
Common attachments and metadata updates require an ACTIVE KB with a valid head;
receipt replay rechecks readiness. Repair rows remain in the registry and the
owner can still tombstone them. Processes running as the store owner retain that owner's authority;
path-component swaps by that identity remain outside the filesystem jail's
protection, as on Unix.

The native CI matrix runs the drain, hung-Git, ACL and junction tests on
`windows-latest`; cross-compilation alone does not certify their runtime
behavior.

Optional local CPU embedding models are controlled by the local owner:

```sh
kb model --root /private/store list --json
kb model --root /private/store enable
kb model --root /private/store enable qwen3-embedding-0.6b-q8_0 --context 2048
kb model download embeddinggemma-2-q8_0
kb model --root /private/store status
kb model verify
kb model --root /private/store disable
kb model --root /private/store remove qwen3-embedding-0.6b-q8_0 --yes
kb providers --root /private/store attach --kb <kbId> --provider builtin
```

Both models start disabled. Enable defaults to EmbeddingGemma 2 Q8_0 and a
1024-token context. The list offers both models at 1K/2K/4K/8K with conservative
memory estimates, available RAM, admission level, whether each is downloaded
and one recommendation (retrieval quality first among options below the 90%
block threshold). Smaller options remain available. Above 70%, enable requires
`--acknowledge-memory-warning`; unknown memory or 90% and above fails closed.
Providers remain an alternative for machines without enough RAM.

Weights live in one per-user cache shared by every store: `kb/models` under
the platform cache directory, or `models_dir` in the config (absolute; another
program's model directory: downloads are installed there when nobody else
can change it, else in the owner-only `verified/` cache; a pinned file `kb`
did not create is copied, checksum-verified, into `verified/` once, because
only files `kb` created itself are ever loaded). Download fetches the commit-pinned GGUF with progress on stderr and
publishes it only after the checksum matches; download alone leaves inference
disabled. Verified weights are never bundled in binaries or images. A
conflicting file is refused, not replaced: `kb model verify` reports it and
`kb model remove <model> --yes` deletes it. Disable persists a new epoch and
keeps the file; in-flight requests of that store fail their next check.

Inference runs in one shared, detached `kb embed-worker` per user, started on
demand and reached over an owner-only Unix socket (a private named pipe on
Windows). It serves every `kb mcp` session and store concurrently with one
model in memory, runs queries ahead of index builds, exits after 15 minutes
without work and is restarted by the next request. Oversize inputs reject
before native execution, including the prompt and exactly-once special tokens.
Gemma uses MEAN pooling and a single full-input batch; Qwen uses LAST pooling
and causal 512-token batches. Outputs are finite raw pooled vectors of 768
and 1024 dimensions respectively (the index normalizes them once).

Building the CLI now needs CMake, a C++ compiler, libclang and OpenMP (plus
C++/OpenMP shared runtime libraries where linked). The approved embedding-only
0.1.160 bindings and unpatched llama.cpp v0.7.0 source are under `vendor/`;
see its README for source pins. Native builds are capped
at three jobs. Standard Cargo tests use real child processes with fake
inference; real-model tests are ignored only in ordinary tests. Explicit smoke:

```sh
cargo build --locked -p kb
KB_MODEL_EXECUTABLE="$PWD/target/debug/kb" \
KB_GEMMA_MODEL_PATH=/private/cache/embeddinggemma-2-Q8_0.gguf \
KB_QWEN_MODEL_PATH=/private/cache/Qwen3-Embedding-0.6B-Q8_0.gguf \
cargo test --locked -p kb-local --test qwen_model -- --ignored --test-threads=1
```

Missing or tampered files fail that command. The required model workflow
selects both tests, asserts a nonzero count, and covers the shipped native
release platforms. Linux memory assertions reject a build that allocates
unused pooled logits. Local host evidence does not certify other
architectures or operating systems.

Unix child shutdown uses the platform `/bin/kill` utility via `exec` so native
exit handlers cannot delay parent-death or revocation cleanup. Parent-owned
watchers force-kill and reap revoked idle children; Windows uses the existing
kill-on-close Job Object for parent death. The model lease lasts through reaping.

Enable downloads without disabling the active model, then load-probes an exact
maximum-context embedding before switching. When both configurations fit below
the 90% memory limit, the old child keeps serving during the probe. Otherwise
the runtime records a reloading gap, drains the old child and restarts its last
good configuration if the probe fails. The active fields always retain the last
good settings until success; interrupted probes are failed on reopen rather
than retried. Hosts configure their existing `ModelRuntime` to retain the probed
child on success and the restarted child on failure. The short-lived owner CLI
drains children when it exits. Download scratch recovery takes a separate
drained lease and removes only recognized private abandoned partial files.

Embedding source input is bounded to 64 KiB of raw UTF-8; its IPC envelope allows
worst-case JSON escaping. Larger raw input and untruncated tokenizer overflow
return `EMBEDDING_INPUT_TOO_LONG`. Expired requests and late replies return
`DEADLINE_EXCEEDED`, including with a previously loaded child.

The complete operational overview is [CLI guide](../../docs/cli.md), with
[MCP wire examples](../../docs/mcp.md), [historical assets](../../docs/assets.md)
and [Cockpit host seams](../../docs/cockpit-adapter.md). `state.sqlite` is not
disposable; missing it in a nonempty store is REPAIR_REQUIRED. Only derived
index generations are rebuildable. Native release targets are Linux static
musl x64/arm64, macOS x64/arm64 and Windows MSVC x64 (Windows 10+). Missing mandatory
platform/model execution is incomplete evidence, never a platform waiver.
